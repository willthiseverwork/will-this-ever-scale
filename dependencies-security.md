# Dependency security — 31 October 2026

A registry-backed `npm audit` after `npm audit fix --ignore-scripts` reported **15 advisories: 14 high, 1 moderate** before adding the requested AWS provider. After `@ai-sdk/amazon-bedrock` was added, a fresh registry-backed audit reports **19 advisories: 16 high, 3 moderate**. The safe fix changed six packages and added two; the unused `@playwright/test` dependency and its packages were removed. The offline uninstall's “0 vulnerabilities” line is not an audit result. No `--force`, major downgrade, or unverified override was applied. The fresh report recommends toolkit/Blob downgrades or Zod 4 migration, all outside a compatible routine patch.

- **Zod collection exhaustion:** root Zod 3.25.76 is used by public API validation and the PayPal toolkit; Blob's CLI-config has an independently pinned Zod 4.1.11. The patched advisory range is Zod 4.6.6 or later, outside the root major and the CLI-config exact pin. All app JSON routes now read and cap incoming bytes before parsing and validation (1–64 KiB depending on route), including chunked requests. This reduces input-driven exhaustion; it is not a proof that all Zod paths or external provider responses are safe. Migrate and integration-test Zod and its callers when their dependencies support a compatible version.
- **PayPal toolkit tree:** the app imports only the toolkit's AI SDK adapter and invokes its invoice-list tool; it does not expose an arbitrary toolkit dispatcher or use the LangChain, OpenAI, MCP, UI-rendering, expression-evaluation, or prompt-deserialization adapters. The package nevertheless installs old `@langchain/core`, `ai` 4, `jsondiffpatch`, `mathjs`, OpenAI SDK and transitive packages flagged by audit. Some code is bundled in the imported adapter, so these boundaries reduce exposure but do not establish non-reachability of every vulnerable function. Patched versions require crossing pinned or major-version boundaries; assess an upstream toolkit release or replacing the single read adapter, with sandbox compatibility tests, before applying overrides.
- **Amazon Bedrock provider:** version 3.0.142 is the matching provider-interface generation for AI SDK 5. It adds advisory paths through its pinned provider-utils 3.0.43 and undici/fastify-busboy. The app sends a small JSON prompt and does not parse user-supplied multipart through this adapter, but these dependencies remain present and that does not prove every vulnerable path unreachable. A second compatible `npm audit fix` found no changes. The provider is inactive unless explicitly configured and production AI remains disabled without the verified limiter and credentials.
- **Blob/OIDC:** the private reminder store uses `@vercel/blob` 2.8.2; its OIDC/CLI-config tree carries the pinned vulnerable Zod 4.1.11. The reminder route limits the input to 2 KiB and validates the exact fields. A compatible upstream CLI-config update remains needed.
- **UUID:** the moderate advisory enters through the toolkit's LangChain tree; the vulnerable buffer-write use is not invoked by app code. It remains an installed dependency and is not claimed fixed.

Tests after updates: TypeScript and the full suite passed 42 tests after the provider addition, including provider selection and streaming-body limits. The production build passed after the provider addition. Live deployed behavior and actual attack resistance were not tested by npm audit. Re-run the registry audit and full suite after future dependency changes.
