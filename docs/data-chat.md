# Data chat

`answerDataChat(analysis, questionOrPlan)` is a synchronous, deterministic, read-only browser-safe function. Text parsing happens locally. It never receives raw CSV rows, sends data, executes SQL, calls a model or performs actions. It reads only the supplied `Analysis`. A separate optional intent parser may suggest a `DataChatPlan`; treat its output as untrusted and pass it through `isDataChatPlan` or `answerDataChat`. Plans admit only the exact fixed keys, metrics and periods in `data-chat-types.ts`. Product names and customer identifiers are not plan fields. Do not send product names or raw questions containing them to a remote model; remote intent phrasing must be redacted, and any results must be recomputed locally.

Rankings cover gross, order rows or refunded/reversed/disputed amount by item group, for a specified calendar month or whole supplied period. Popularity without a metric gets a clarification; units are unavailable. Relative month expressions use the analysis clock; a missing period defaults to the latest available completed month, stated in the result. Last three months includes the current month, with a partial-month caveat when applicable. For a fixed analysis clock on the last day of its month, the existing read treats that month as complete. “Last month” means the preceding calendar month; answers show the selected month explicitly. Month comparisons require two resolved calendar months and an available common metric. Daily data is unavailable in this aggregate. Results identify analysis fields and coverage caveats. Current-month results are partial as of the analysis clock. No calculation establishes the cause of a result. Unlabelled groups may hide individual product rankings; refunded amounts are event-period figures, not rates or original sale cohorts. Analysis currency selection, costs and other source limits are documented in `calculations.md`.

`merchantKnowledge` is a fixed set of optional research prompts, with prerequisites, possible explanations, neutral questions, tests and sources. Reddit accounts are anecdotal; do not present them as prevalence, causal proof, or evidence about the current seller. Questions are suggestions, not permission to contact customers. The existing playbook remains independent and unchanged.

The hosted production build passed 165 tests and compilation/type checking; a production audit covered 21 route/viewport checks. An earlier production audit recorded one real AI intent response with HTTP 200. These checks do not establish every data-chat edge case or a private account lifecycle; continue to verify coverage, privacy and malformed plans as those features change.

Optional AI intent integration: send only fixed semantic tokens and available month IDs; the question text and product labels stay in the browser. Accept only the strict `parseDataChatPlan` output; never execute model instructions or SQL. Compute the result locally using the returned plan. Do not send raw rows, product names or CSV to a server model. A separate user-authorized external plugin is outside this interface.
