# WTES account and workspace foundation

Use a separate WorkOS AuthKit application and a separate private Blob store. Configure `WTES_WORKOS_CLIENT_ID`, `WTES_WORKOS_API_KEY`, `WTES_SESSION_SECRET` (at least 32 random bytes), `WTES_APP_ORIGIN` (exact HTTPS origin without trailing slash), `WTES_WORKSPACE_STORE_ID` (preferred, using Vercel OIDC) or the explicit legacy `WTES_WORKSPACE_BLOB_TOKEN`, and `WTES_WORKSPACE_SECRET` (at least 32 independent random bytes). The explicit store ID takes precedence; an invalid ID or unavailable OIDC fails closed and never falls back to the default Blob token or the legacy workspace token. When the ID is absent, only the explicit workspace token is used. Do not reuse Review Intel credentials or storage. Register the exact callback `https://<WTES host>/api/account/callback` in the WTES WorkOS application, enable AuthKit, and use a private Blob store. The production runtime is deployed, but account storage is not configured; the production account check returned `configured:false`. Missing configuration returns unavailable rather than simulated sign-in.

WorkOS authorization code uses state and S256 PKCE; transient flow and five-minute app session cookies are encrypted, HttpOnly, Secure, and SameSite=Lax. The access session lasts at most five minutes; an encrypted HttpOnly refresh cookie rotates through WorkOS and the application refreshes it while active. Provider revocation may take until the short access session expires. Logout clears local cookies and requests WorkOS session revocation; a provider error is reported. Verify account deletion, revocation and incident response before release.

Only bounded, allowlisted numeric snapshots and enum/date reminder and experiment records are stored, encrypted in private Blob under an HMAC-derived user path. No raw CSV or transaction identities are accepted. Optional user-supplied product labels are private workspace aggregates; users must avoid customer names or other personal information in labels. Labels are limited to 120 characters with control characters removed. They are available to Claude or Codex only when the explicit `shareProductNamesWithAssistant` setting is true; integrations must enforce this on every model or MCP response. Consent defaults to false and can be changed in the workspace. PUT is a full replacement with revision-based conflict detection; reload on 409. The first successful nonempty snapshot save starts the 30-day trial; signing in and saving empty records do not start it. Trial dates persist if snapshots are later deleted. When billing is enabled, expired trials require an active paid subscription for new workspace saves; read, export and delete remain available. Billing is currently off. The trial requires no card and creates no automatic charge. Reminders are in-dashboard records only; no email or notification is sent.

Before account activation, verify the real WorkOS round trip, denial and expired state, CSRF rejection, two-account isolation, private Blob encryption and conflicts, first-save trial and boundary, logout, data deletion/retention process, and mobile/account UI. Verify provider configuration and secrets in the intended production environment; do not put them into source or client code. Check public privacy disclosures, analytics exclusions, accessibility and the applicable public launch checklist. The hosted production build passed 165 tests and compilation/type checking. Production route and viewport checks covered the public and unconfigured states; they do not prove an account lifecycle. No real account, provider configuration or private workspace lifecycle was exercised.

Snapshot `source` is a client-reported import label, not server-verified PayPal provenance. Month and opaque item identifiers provide numeric summaries; optional reviewed labels are retained only when explicitly supplied. Opaque IDs are scoped to the submitted snapshot and do not establish cross-snapshot product identity. Reminder and test finding IDs come from the fixed playbook; derive display names from the playbook. Never infer provider verification from the source label.

Provider reference: https://workos.com/docs/reference/authkit/authentication/get-authorization-url and https://workos.com/docs/reference/authkit/authentication .

`DELETE /api/workspace` requires the authenticated session and exact same origin. It clears snapshots, labels, reminders, tests and name-sharing consent, while retaining encrypted trial dates and a revision tombstone to prevent trial resets and stale writes. It does not delete the WorkOS account or sign the user out. A simultaneous write can return 409; reload before retrying. Provider account deletion and retention policy need separate implementation and verification.

Product labels must be explicitly reviewed (`labelReviewed: true`) and cannot contain obvious email addresses, phone numbers or URLs. The checks cannot detect all personal information. Legacy unreviewed labels are stripped on read. Coverage gaps use fixed codes and are retained with snapshots. Snapshot period boundaries have month precision; `date_coverage_unknown` records when exact date coverage is unknown.
