# Shared AI model-call allowance

The allowance is 500 model HTTP invocations per UTC calendar month across instances. Enforcement belongs at the shared production OIDC provider fetch boundary: immediately before **each** model HTTP invocation, including any retry, call `reserveAiBudget()` and proceed only if `allowed` is true. A failed or exhausted reservation must not send a provider request; existing callers fall back to their deterministic templates. Aggregate reads may make more than one model call, and each consumes its own slot. The fictional sample read uses a reviewed static cache or template without a model call; the shared sandbox snapshot can use model grouping when refreshed. The ordinary Nova provider boundary rejects inputs over 12,000 bytes and outputs above 300 tokens, and disables model reasoning. The separate voice transport has its own bounded reasoning allowance; see [voice](voice.md).

This guard protects only calls that pass through the guarded provider. New non-voice AI endpoints must use that provider rather than invoke a model directly; the separately bounded voice transport also reserves the shared allowance; another application or credential is outside this control. The per-IP firewall is independent. The provider integration and its production behavior must be verified before claiming all paths are covered.

A $0.02 planning allowance per call corresponds to $10 estimated monthly usage at 500 calls. This is an internal reservation count, **not an AWS spending limit, actual-cost measurement, guarantee that a call costs at most $0.02, or limit on other applications**. Actual usage depends on current provider prices, token use, retries and other services. Check provider usage and billing separately.

The private Vercel Blob record `ai-budget/YYYY-MM.json` contains only `{version, month, count}`. Origin reads bypass the CDN. Initial creation does not overwrite an existing record; subsequent updates use the last observed ETag as `ifMatch`. The guard attempts at most three recognized concurrency conflicts and permits no value above 500. A lower cap can be supplied by a trusted caller; zero disables the allowance. It never automatically refunds a reservation after a failure, timeout, invalid output or fallback because a provider call may already have occurred.

No Blob credential, unsupported private storage, invalid record, read/write error, timeout, exhausted allowance or unresolved conflict permits the guarded model call. Contention at initial creation may conservatively return unavailable if the storage SDK does not identify the race as a precondition conflict. A missing budget record starts a new month; the store and its records must be preserved. Deleting or replacing a record can reset or distort the count, and a Blob failure may make AI unavailable. No customer data, prompts, model output or identities belong in the counter record.

The budget guard must be validated against the actual private store before claiming it works in production. Unit fixtures use an injected in-memory store and do not prove production Blob configuration or provider costs.
