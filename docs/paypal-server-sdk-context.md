# PayPal Server SDK context plugin: sandbox order verification

The hackathon preview repository is a context/instruction plugin, not a runtime SDK or a long-term supported PayPal product. Its README and TypeScript skills were read from commit `6aa057126f0d4709a42e15002aab832a94935d92`: [preview repository at commit](https://github.com/paypaldev/server-sdk-context-plugin-preview/tree/6aa057126f0d4709a42e15002aab832a94935d92). The materials used were `typescript-getting-started`, `typescript-client-initialization`, `typescript-authentication`, `typescript-calling-endpoints`, `typescript-models`, `typescript-error-handling`, `typescript-configuration-resilience`, and `typescript-testing` under `skills/typescript/`.

For a remaining genuine gap—read-only confirmation of a specific sandbox order and its capture evidence—`scripts/verify-sandbox-order.ts` uses the pinned APIMatic-generated `@paypal/paypal-server-sdk` 2.5.0. Actual installed SDK source was inspected for `Environment.Sandbox`, `clientCredentialsAuthCredentials`, `OrdersController.getOrder`, response `.result`, `purchaseUnits[].payments.captures`, and `ApiError.statusCode`. It explicitly sets a 15-second per-request timeout, disables retries, and uses the default null logger. A completed order without a visible completed capture is **not** called captured. No payer details or provider error body are returned.

Authorized local use, after obtaining the exact sandbox order ID and sandbox credentials: set `PAYPAL_SANDBOX_CLIENT_ID` and `PAYPAL_SANDBOX_CLIENT_SECRET` in the invoking process, then run `node --import tsx scripts/verify-sandbox-order.ts ORDER_ID`. The command performs read-only OAuth and order GET requests. It does not create, approve, capture, refund, cancel or otherwise change an order; no real sandbox order was queried in development. A missing capture list is `not_observed`, not proof that capture never occurred. Token acquisition and order GET each have their own timeout.

`tests/paypal-server-sdk.test.ts` exercises the real generated controller with the plugin's `unstable_httpClientOptions` axios-adapter seam, dummy OAuth, and mocked responses. It checks the sandbox GET, a completed capture, missing capture evidence, sanitized 403, and that payer email is omitted. No external credentials or account mutations were used in the tests. This new diagnostic does not retroactively change earlier PayPal results or claim earlier use of the plugin.
