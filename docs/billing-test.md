# Owner-only Paddle sandbox acceptance

`/billing-test` is a private, noindex page with no normal-app navigation. It returns not found unless the test is enabled, all dedicated sandbox settings are present, and the existing verified WorkOS session belongs to the exact configured owner. The page does not render account identifiers or provider keys. A recently expired access session must be refreshed through the existing account flow before opening the page. Test APIs repeat the owner check, and mutations require same-origin requests and session renewal.

The page says **Payment test — no real money** and always opens Paddle sandbox checkout or the sandbox customer portal. The server chooses the test phase; browser input, query parameters and request bodies do not choose an environment, date, owner or trial phase. A synthetic test-trial action writes only to the dedicated test record. It does not save a real workspace summary or start a real workspace trial. Test payment, cancellation and reactivation actions are not initiated automatically; each requires its own explicit action and applicable user authorization. A checkout overlay or client event does not prove payment, entitlement or a real customer lifecycle.

The default is off. Dedicated setup requires `WTES_BILLING_TEST_ENABLED`, `WTES_BILLING_TEST_OWNER_USER_ID`, `WTES_BILLING_TEST_PADDLE_API_KEY`, `WTES_BILLING_TEST_PADDLE_CLIENT_TOKEN`, `WTES_BILLING_TEST_PADDLE_PRICE_MONTHLY`, `WTES_BILLING_TEST_PADDLE_WEBHOOK_SECRET`, `WTES_BILLING_TEST_SECRET`, `WTES_BILLING_TEST_BLOB_TOKEN`, and a server-selected `WTES_BILLING_TEST_PHASE` (`active` or `expired`). Use a dedicated sandbox catalog, notification destination, private test storage and independent secrets. Never reuse live or Review Intel credentials. Creating or changing provider resources, settings, credentials or subscriptions requires its own authority; this source change configures none of them. Active and expired phases use separate synthetic trial records. Changing a server phase is a test-environment operation, not an end-user control.

Before any hosted acceptance action, verify the exact owner, sandbox API and client token, price, webhook endpoint and isolated test storage. Check anonymous, nonowner, disabled, missing-config, expired-session and cross-origin rejection; verify no page or data is exposed, no public links or sitemap entry exist, and status/checkout/portal results use only sandbox. Then, under explicit authority, test first synthetic save, active trial without checkout, expired trial checkout, webhook confirmation, portal, cancellation and reversal, reload/retry and error states. Confirm ordinary production billing remains off and real workspaces are untouched. Provider setup, hosted checks and a complete sandbox lifecycle have not been performed by this source change.

Paddle documents the sandbox portal host at https://developer.paddle.com/changelog/2025/subscription-management-links-customer-portal/ .

For a Paddle sandbox payment link, the page removes `_ptxn` from the visible browser URL and offers an explicit continue control only if that reference exactly matches the current owner-bound transaction returned by the test API and checkout is permitted. Before opening the overlay it renews the session and reads the server state again; it accepts only a sandbox client token and does not create a new transaction. An arbitrary, duplicate, malformed or mismatched reference is not opened.

The test transaction explicitly sets `checkout.url` to the canonical `/billing-test` page, without altering the merchant-wide default. Paddle documents that it appends the transaction ID as `_ptxn`; the owner UI must compare it with the server-bound pending test transaction before offering to continue. The sandbox API key must use the modern `pdl_sdbx_` prefix and the client token must start with `test_`; test secrets and storage token must differ from configured billing and workspace equivalents. Signed notifications for other products are acknowledged without provider reads or state changes. A matching owner or subscription event remains subject to the full transaction, nonce and provider verification. See [Paddle transaction creation](https://developer.paddle.com/api-reference/transactions/create-transaction/) and [sandbox credentials](https://developer.paddle.com/sdks/sandbox/).
